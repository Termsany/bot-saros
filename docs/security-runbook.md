# لو حصلت مشكلة أمان: تعمل إيه (خطة التأمين، المرحلة 3، 2026-11-08)

القاعدة في كل الحالات:
- **الصفقات المفتوحة على Binance آمنة بالوقف بتاعها** حتى لو البوت وقف. ماتقفلش صفقات بإيدك وانت مستعجل.
- **أول حاجة: اقفل الدخول. بعدها افهم اللي حصل.**
- كل خطوة هنا بتعملها انت بنفسك. المفاتيح والباسوردات مابتتكتبش في أي شات.

## 1. الموبايل اللي عليه الـ 2FA ضاع أو اتسرق
1. ادخل Supabase من الكمبيوتر: **Authentication ← Users ← حسابك ← MFA factors ← Delete**. الحذف بيشيل الـ 2FA.
2. افتح صفحة الأدمن وفعّل الـ 2FA من جديد على الموبايل الجديد.
3. من القائمة: **"اخرج من كل الأجهزة"**. ده بيخرّج أي جلسة كانت فاتحة على الموبايل القديم.
4. لو الموبايل كان عليه Telegram: من Telegram على جهاز تاني ← Settings ← Devices ← اقفل الجهاز القديم.

## 2. مفتاح Binance بتاع مستخدم اتسرّب
1. **المستخدم:** يمسح المفتاح من Binance (API Management ← Delete). ده أسرع وأضمن حل، لأن المفتاح من غيره مالوش أي لازمة.
2. **انت:** في صفحة الأدمن ← "بوتات المستخدمين" ← شيل موافقة المستخدم ده.
   - الـ provisioner بيوقف الدخول فوراً.
   - البوت بيقفل لما المستخدم يبقى من غير صفقات.
3. لو عاوز يكمّل: يعمل مفتاح جديد بنفس الشروط (Reading وFutures بس، ومقفول على IP السيرفر) ويحفظه في خطوة 1. السيرفر بيفحصه لوحده.
4. راجع رسايل التليجرام ("💰 مستخدم") من ساعة التسريب: فيها أي تغيير اتعمل على فلوسه الحقيقية.

## 3. باسورد الأدمن اتسرّب
1. غيّر الباسورد فوراً: Supabase ← Authentication ← Users ← حسابك ← Send password recovery. أو من صفحة الدخول ← "نسيت الباسورد".
2. **"اخرج من كل الأجهزة"** من القائمة. أي جلسة مسروقة بتقف في خلال دقيقة تقريباً.
3. اتأكد إن الـ 2FA لسه بتاعك: Supabase ← MFA factors لازم يكون فيه موبايلك بس. لو فيه حاجة غريبة، امسحها وفعّل من جديد.
4. راجع رسايل التليجرام ("🔐 أدمن"، ومنها "دخول جديد" لكل جلسة أدمن جديدة)، وصفحة **نشاط الحساب** (من القائمة: كل دخول بالجهاز والـ IP، وكل تغيير مهم)، وسجل الأدمن (audit) من وقت التسريب. أي تغيير ماعملتوش، رجّعه.
5. لو لسه مافعلتش البند 6 (`ADMIN_REQUIRE_MFA=1`)، فعّله دلوقتي: من غيره، أي حد معاه الباسورد وماعندوش 2FA بيقدر يدخل.

## 4. شك إن السيرفر نفسه اتخترق
**اقفل الفلوس الحقيقية الأول:**
1. صفحة الأدمن ← زرار فلوس المستخدمين الحقيقية ← **قفل**.
2. root على السيرفر: `rm /etc/raqm-users/live.enabled`. ده القفل اللي الموقع مايقدرش يفتحه تاني.
3. **في Binance:** امسح الـ API keys بتاعة كل حساباتك (الرئيسي والـ sub-accounts). البوتات مش هتقدر تبعت أوامر، والصفقات بتفضل بوقفها. وقول للمستخدمين يمسحوا مفاتيحهم كمان.

**بعدها غيّر كل المفاتيح** (من جهازك، مش من السيرفر لو مش واثق فيه):

| المفتاح | فين |
|---|---|
| مفتاح SSH بتاعك وبتاع Claude | `~/.ssh/authorized_keys` على السيرفر. امسح الكل، وحط المفاتيح الجديدة بس |
| Supabase service role key | Supabase ← Settings ← API ← Roll |
| Telegram bot token | BotFather ← /revoke، وبعدها حط الجديد في `.env.telegram` و`/opt/raqm-api/.env` |
| مفتاح خزنة المستخدمين (`VAULT_MASTER_KEY`) | مفتاح جديد في `/opt/raqm-api/.env`، وبعدها `rekey_user_vault.py` (موجود في `/usr/local/lib/raqm/`) بيعيد تشفير الخزنة بيه. أو ببساطة المستخدمين يحفظوا مفاتيح جديدة |
| مفتاح النسخ الاحتياطية | مش محتاج يتغيّر: السيرفر عليه الـ public key بس. الـ private key عندك انت |

**وبعدين:**
- لو مش متأكد إن السيرفر نضيف: سيرفر جديد، و`setup-live.sh`، وترجّع السجلات من النسخة الاحتياطية (`docs/restore.md`).
- ماتشغّلش الفلوس الحقيقية تاني غير لما تعرف إزاي حصل الاختراق.

## 5. حاجات تتعمل من دلوقتي علشان الخطوات دي تنفع
- الـ private key بتاع النسخ الاحتياطية عندك على جهازك، ونسخة على فلاشة (`docs/restore.md` §0).
- كود الاسترجاع (recovery codes) بتاع Binance وSupabase مكتوب ومحفوظ برّه الموبايل.
- الـ 2FA على Binance نفسه مفعّل، وعلى Telegram (باسورد Two-Step Verification).
- إيميلك (اللي Supabase وBinance بيبعتوا عليه) عليه 2FA. لو الإيميل اتسرق، كل حاجة تانية ممكن تتسرق.
