## P1 — Security

| ID | Severity | File:Line | Status | Finding |
|---|---|---|---|---|
| P1-01a | HIGH | `backend/app/main.py:273-281` (`GET /api/chart`) | **Confirmed** | **IDOR — unauthenticated info disclosure.** `api_chart(file: str)` has NO `Depends(require_user)` / admin guard. An authenticated attacker can read another user's `backtest_*.png/json` by guessing `uuid4 hex` (filenames are pseudo-random via `BotDir/backtest_*.png`), and any unauthenticated caller can read them directly when `ALLOW_LIVE_TRADING` / docs are off. Path validation (`backtest_[A-Za-z0-9_]+_[0-9a-f]{10}`) limits traversal but not cross-user access, and opaque IDs are not access control. |
| P1-02 | MEDIUM | `backend/app/llm_sandbox.py:103-138` | **Confirmed (limitation)** | **LLM sandbox is best-effort, not isolation.** `validate_code` is AST allow-list + `run_backtest_sandboxed` runs a separate `python -I` with `PYTHONPATH` stripped, temp cwd, `RLIMIT_CPU/AS/NOFILE/AS` + timeout. No container/network/filesystem namespace, no seccomp, no read-only root, no memory cgroup beyond 1GB soft limit, and `preexec_fn` is Linux-only (no-op on Windows). `FORBIDDEN_ATTRS`/`ALLOWED_IMPORTS` is an LLM-curated blocklist (brittle). Guidance in-file says "defense in depth, not a perfect sandbox" — correct. Production hardening per Master §P1-02 (dedicated container, no network/volume mounts, CPU/mem limits) is still absent. |
| P1-03a | MEDIUM | `backend/app/keys_vault.py:26-44` | **Confirmed** | **Master key still co-stored with ciphertext on local FS.** `VAULT_MASTER_KEY` env is preferred, but fallback generates `../.master.key` (chmod 600) next to `vault.json` — exactly the "protect encryption keys separately from encrypted data" violation. Rotation supported only by rewriting the file; no re-key API. Secrets are never logged, but file-permission enforcement is `try: chmod(0o600) except: pass` (no verification). |
| P1-03b | LOW | `backend/app/keys_vault.py:44-68` (`save_keys`/`load_keys`) | **Confirmed** | Broad `except: data = {}` / `return None` on vault decrypt swallows `Fernet` failures, turning a corrupted vault into a silent empty store. No fail-closed on bad key. |

| P1-04b | MEDIUM | `backend/app/auth.py:66-90` | **Confirmed (robust)** | Authentication via `GET /auth/v1/user` (works for HS256 + asymmetric), `require_admin` via `ADMIN_EMAILS` set + email-confirmed guard, `require_admin_or_cron` via `X-Cron-Secret`. `keys_vault` per-file audit already covers admin routes.
